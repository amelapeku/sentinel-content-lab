# Sentinel Content Lab (TTT)

This repository is connected to a Microsoft Sentinel workspace through the **Defender portal → Microsoft Sentinel → Configuration → Repositories** feature.

Every push to the `main` branch triggers a GitHub Actions workflow that deploys the changed files into Sentinel.

## Folder layout

| Folder | Content type | Bicep resource |
|--------|--------------|----------------|
| `analytics-rules/` | Scheduled analytic rules | `Microsoft.OperationalInsights/workspaces/providers/alertRules` |
| `parsers/` | ASIM / custom parsers (saved functions) | `Microsoft.OperationalInsights/workspaces/savedSearches` |
| `workbooks/` | Workbooks | `Microsoft.Insights/workbooks` |

## Files at the root

| File | Purpose |
|------|---------|
| `sentinel-deployment.config` | Optional. Prioritize, exclude, and map parameter files. |
| `.github/workflows/sentinel-deploy-*.yml` | **Auto-generated by Defender.** Don't edit unless you know what you're doing. |
| `.sentinel/Tracking_Table_*.csv` | **Auto-generated by Defender.** Smart-deployments audit log. |

## Local Bicep tooling (optional)

```powershell
az bicep install      # one-time
az bicep build --file analytics-rules/mass-file-download.bicep
```

This produces the ARM JSON the deployment action ultimately submits. Useful for catching syntax errors before you push.
